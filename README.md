## Deploy to GitHub Pages

You need a free GitHub account. Total time: about ten minutes.

### Step 1 — Create the repository

1. Go to **github.com** and sign in.
2. Click the **+** in the top right, then **New repository**.
3. Repository name: `swetharamar.github.io` — replace `swetharamar` with your exact GitHub username. The name must match your username or the site will not publish at the short URL.
4. Set it to **Public**.
5. Do **not** tick "Add a README file".
6. Click **Create repository**.

### Step 2 — Upload the files

1. On the new empty repository page, click **uploading an existing file**.
2. Drag in `index.html` and the `assets` folder (with your photo inside it).
3. In the box at the bottom, type `Add portfolio site`.
4. Click **Commit changes**.

### Step 3 — Turn on Pages

1. In the repository, click **Settings** (top row).
2. In the left sidebar, click **Pages**.
3. Under **Source**, choose **Deploy from a branch**.
4. Branch: **main**. Folder: **/ (root)**. Click **Save**.
5. Wait two to three minutes.

### Step 4 — Open your site

Your site is live at:

```
https://YOUR-USERNAME.github.io
```

Refresh the Pages settings screen if it isn't up yet. The first publish is the slowest one.

## Making changes later

1. Open the repository on GitHub.
2. Click `index.html`.
3. Click the pencil icon (top right of the file).
4. Edit the text.
5. Scroll down, click **Commit changes**.

Your live site updates in about a minute.

## A note on what is not in here

This site describes client work without naming clients and without reproducing any client document. That is deliberate. Process manuals, test cases, field mappings and migration runbooks belong to your employer and their clients, and publishing them would breach the confidentiality terms you work under.

If an interviewer wants evidence, show redacted samples in the interview. That is the normal professional route and it demonstrates better judgment than publishing them ever could.
